# AGENTS.md - AI Contributor Guide

This file is for any AI coding assistant (Claude, Codex, Cursor, etc.) working in this repository. It is the single source of truth for agent rules — other files (e.g. `CLAUDE.md`) point here instead of duplicating content.

## Response Style

- **All responses must be given using `/caveman ultra` mode, in English.**

## Goal

- Keep the starter aligned with Shopify docs-first patterns.
- Keep TypeScript for behavior and Liquid for markup.
- Keep customization safe via stable `data-js` contracts.

## Core JS Rule

**Each page loads only the JS it needs.**

The centralised router in `layout/theme.liquid` uses `request.page_type` to include
the correct entrypoint. Render entries as `{% render 'vite-tag', entry: 'product.ts' %}`. Never add `vite-tag` inside section files —
loading is handled exclusively by the layout.

| Always loaded | Template-specific only |
|---|---|
| `css/main.css` | `ts/index.ts` (homepage) |
| `ts/theme.ts` | `ts/product.ts` (PDP) |
| | `ts/collection.ts` (PLP) |
| | `ts/cart.ts`, `ts/search.ts`, etc. |

`ts/gift-card.ts` is the only exception: loaded directly in `templates/gift_card.liquid`
because that template uses `{% layout none %}`.

## Non-Negotiable Rules

- Do not generate cart/minicart/search HTML strings in TS.
- Do not add `{% render 'vite-tag' %}` in sections/snippets.
- Keep entrypoint routing centralized in `layout/theme.liquid`.
- Keep API calls user-driven where required by this starter architecture.
- Keep behavior and state orchestration in TypeScript modules under `frontend/entrypoints/ts/**`
- Keep editable markup in Liquid sections/snippets under `sections/**` and `snippets/**`
- Treat `data-js` attributes as the integration contract between TS and Liquid
- Font sizes use the type scale tokens in `css/typography.css` (`--text-label` 12px floor, `--text-sm`, `--text-base`, `--text-lg`); never set running text below `--text-label`
- Do not move markup generation into TS string templates for cart/minicart/search flows

## Where to Implement Changes

- Global bootstrap: `frontend/entrypoints/ts/theme.ts`
- Shared logic/utilities (e.g. modal, DOM helpers): `frontend/entrypoints/ts/utils/*`
- Cart drawer logic: `frontend/entrypoints/ts/cart/drawer.ts`
- Cart page logic: `frontend/entrypoints/ts/cart/page.ts`
- Product logic: `frontend/entrypoints/ts/product.ts` + `frontend/entrypoints/ts/product/*`
- Collection logic: `frontend/entrypoints/ts/collection.ts`
- Search drawer logic: `frontend/entrypoints/ts/search/drawer.ts`
- Liquid markup: `sections/**`, `snippets/**`

**Never create a new entrypoint** without also (1) adding it to `entries` in `vite.config.js` (entry keys are flat names like `product.ts`, no `/`) and (2) updating the router in `layout/theme.liquid`.

Current interaction ownership:
- `ts/theme.ts`: global cart drawer bootstrap
- `ts/product.ts`: PDP variants/media/add-to-cart states
- `ts/collection.ts`: PLP sort/filter/pagination progressive interactions (type chips reuse `collection-filter-remove`)
- `ts/cart.ts`: cart page quantity/remove interactions
- `ts/search.ts`: predictive search interactions

## Shopify Patterns Required

- Cart mutations use bundled section rendering (`sections`, `sections_url`).
- Single section rendering (`?section_id=`) is used only where explicitly intended (e.g. drawer hydration).
- PDP/PLP add-to-cart calls the standard `Shopify.actions.updateCart`/`openCart` (configured in `cart/drawer.ts`) instead of the raw AJAX Cart API, so external apps/agents calling the same actions get the same drawer UX. Internal drawer/cart-page qty/remove interactions stay on the direct AJAX Cart API.
- Locale-aware routes use `window.Shopify.routes.root`.

- Product: `product-gallery` (Embla, `data-carousel-owned`), `media-item`, `gallery-index`, `product-qty-dec`, `product-qty-inc`, `add-to-cart-label`, `product-form`, `product-data`, `variant-prices`, `variant-compare-prices`, `variant-id`, `option-value`, `option-label`, `thumbnail`, `product-price`, `product-compare-price`, `product-availability`, `product-specifications`, `product-spec-variant`, `add-to-cart`, `cart-status`, `recommendations`, `product-recommendations-root`
- Collection (PLP root `collection-root`): `collection-controls`, `collection-products`, `collection-pagination-wrap`, `collection-status`, `collection-error`, `collection-sort`, `collection-clear`, `collection-filter-remove`, `collection-active-filters`, `collection-default-pagination`, `collection-filters-open`, `collection-filters-close`, `collection-filters-drawer`, `collection-filters-panel`, `collection-filters-overlay`, `collection-filters-apply` (submit + close drawer), `collection-range`, `collection-range-min`, `collection-range-max`, `collection-range-output`, `collection-product-card`, `collection-quick-buy`
- Product card (used inside `collection-product-card`, also on PLP grids): `card-price`, `card-variant-picker`, `card-option-value`, `card-product-data`, `card-variant-prices`
- Search drawer: `search-drawer`, `search-drawer-panel`, `search-open`, `search-close`, `search-drawer-form`, `search-drawer-input`, `search-drawer-status`, `search-drawer-error`, `search-drawer-loader`, `search-drawer-empty`, `search-drawer-results`, `search-drawer-groups`
- Header: `site-header` (scroll state), `mobile-menu`, `mobile-menu-close`; icons use `data-lucide` and are hydrated by `ts/theme.ts`.
- Motion (`ts/utils/motion.ts`): GSAP + ScrollTrigger + SplitText, Lenis on the GSAP ticker. `data-reveal` presets: default (rise + fade), `title` (SplitText per-line mask, yPercent 105→0), `image` (inner img scale 1.12→1, no opacity), `fade`; optional `data-reveal-delay` / `-start` / `-duration` / `-stagger`. Hidden states set by JS only. `data-parallax` (ScrollTrigger scrub on `--parallax-y`), `data-lenis-prevent` (opt a scroll container out of Lenis; dialogs are excluded automatically).
- Carousels (`ts/utils/carousel.ts`, Embla): `data-carousel` root (optional JSON options), `data-carousel-viewport`, `data-carousel-prev`, `data-carousel-next`; `data-carousel-owned` = a page module inits it (generic ones are lazy-loaded by `ts/theme.ts`); `data-carousel-static` is set when nothing scrolls.
- Entrypoints start via `onReady()` (`ts/utils/ready.ts`), never a bare `DOMContentLoaded` listener: in Vite dev the module can evaluate after the event.
- Destination pages (`ts/metaobject.ts`, page_type `metaobject`): `destination-nav`, `destination-gallery`, `gallery-filter`, `gallery-count`, `gallery-photo`, `gallery-lightbox`, `gallery-lightbox-image`, `gallery-lightbox-caption`, `gallery-lightbox-index`, `gallery-prev`, `gallery-next`, `gallery-close`, `destination-booking`. Destination buttons read the metaobject `booking_url` / `brochure_url` when their own link is empty.
- Slideshow (`ts/utils/slideshow.ts`, lazy-loaded by theme.ts): `data-slideshow` (optional `data-interval` ms), `data-slide`, `data-slide-to` dots. `data-parallax-target` moves a whole slideshow layer instead of the first img.
- Generic modal (`ts/theme.ts`): `data-dialog-open="<dialog id>"` opens a `<dialog data-dialog>`; `data-dialog-close` or a backdrop click closes it. Only `dialog[data-dialog]` is handled (cart/search drawers keep their own logic).
- Title reveal wraps forced line breaks in `span.reveal-break`; style accent words with `span:not(.reveal-break)`, never a bare `h1 span`.
- Home hero (`ts/index.ts`): `hero-video`, `hero-film`, `hero-film-open`, `hero-film-close`, `hero-film-frame`

## Theme Preview

### Prerequisites

```bash
bun install
cp example.shopify.theme.toml shopify.theme.toml
```

### Store configuration

- `shopify.theme.toml` controls Shopify CLI environment
  - `[environments.development]`
- Keep `shopify.theme.toml` local (gitignored) and commit only `example.shopify.theme.toml`

### Local dev (recommended for daily development)

```bash
bun run dev
```

- Shopify CLI at `http://127.0.0.1:9292`
- Vite at `http://localhost:5173` (HMR active)
- CSS/JS served directly from the Vite dev server

### Theme Editor dev (live updates in the editor, no tunnel)

```bash
bun run dev:editor
```

- Runs `vite build --watch`; Shopify CLI syncs hashed assets to the dev theme
- Full-page reload after each sync (~1-2 s)
- The plugin may hint that `.gitignore` lacks generated-file patterns. Ignore it: assets are committed here, and `main.css` uses `@import "tailwindcss" source(none)` with explicit `@source`s so Tailwind does not rebuild in a loop

### Liquid inspector (Vite DevTools)

- `bun run dev` serves Shopify CLI from the instrumented mirror `.shopify-devtools/theme` (`SHOPIFY_FLAG_PATH`)
- Open the "Shopify Liquid" panel in the Vite DevTools dock, "Inspect page" to pick a component, Enter to open its source
- First connection: authorize the browser with the one-time link/code Vite prints
- Never edit files inside `.shopify-devtools/` (gitignored mirror)

### Deploy

```bash
bun run build
```

Builds production assets for branch-linked Shopify themes.

### Branch-Linked Shopify Deploy Note

If your Shopify theme is connected directly to a Git branch (no `shopify theme push`), you must commit built assets to the branch.

Required flow:
1. Run `bun run build`
2. Commit generated files (`assets/*`, `assets/vite-manifest.json`, `snippets/vite-tag.liquid`)
3. Push the branch

Important:
- CI checks/builds do not automatically update your branch unless the workflow commits artifacts.
- Shopify does not run `vite build` for branch-linked themes.

## Git and Branch Strategy

### Branch model

- `main`: production-ready branch (connected to the production Shopify theme)
- `staging`: QA/integration branch (connected to a staging Shopify theme)
- `feat/*`: feature branches (isolated development work)

### Merge flow

1. Build on `feat/<feature-name>`
2. Open PR to `staging`
3. QA on the Shopify theme linked to `staging`
4. Merge `staging` into `main` for release
5. Keep `main` always releasable

### Start feature branch

```bash
git checkout staging
git pull
git checkout -b feat/<feature-name>
```

### PR quality gates

Before merging to `staging` or `main`, ensure:
- `bun run typecheck` passes
- `bun run build` passes
- `theme-check` passes
- Smoke test the templates touched by the PR
- Verify manual QA on touched templates (PDP, PLP, cart page, minicart as relevant)

CI enforces branch flow **only if the repo is private**:
- PR to `staging` must come from `feat/*`
- PR to `main` must come from `staging`

If the repo is **not private**, this is not enforced — work directly on a shared `staging` branch, then merge `staging` into `main`.

### Naming conventions

- TS entrypoints: match the Shopify `request.page_type` value
- Sections: `{page_type}.liquid` (e.g. `product.liquid`, `blog.liquid`)
- Snippets: descriptive kebab-case name

### Component Documentation

Every snippet, block, and section must start with a LiquidDoc block (`{% doc %}...{% enddoc %}`) describing its purpose, `@param`s, and one `@example`. Follow the existing style in `snippets/image.liquid` and `blocks/group.liquid`. This currently covers `snippets/` and `blocks/` but not `sections/` — new or edited section files must add it too.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| CSS not loading | Vite not running | `bun run dev` |
| Theme Editor not updating | HMR only in local preview | `bun run dev:editor` |
| DevTools "Unauthorized" | Browser not trusted | Use one-time link/code printed by Vite, reload |
| `LOCK_ACTIVE` | Another Vite process owns the theme | Stop it, or remove `.vite-shopify-theme.lock` after a crash |
| Port 5173 already in use | Stale Vite process | `lsof -nP -iTCP:5173 -sTCP:LISTEN` then kill PID |
| Port 9292 already in use | Stale Shopify CLI process | `lsof -nP -iTCP:9292 -sTCP:LISTEN` then kill PID |
| CORS error on `/api/collect` | Shopify analytics on local origin | Non-blocking warning, safe to ignore in dev |

## Working with AI Assistants Efficiently

### Reduce token usage

- **Always name the file first**: "edit `sections/product.liquid`" not "edit the product page"
- **Reference line numbers** when possible: "line 15 in `layout/theme.liquid`"
- **One task at a time**: confirm before moving to the next step
- **Skip general Shopify/Vite explanations** unless strictly needed

### Recommended task format

1. Target file (`sections/collection.liquid`)
2. Goal (what it should do)
3. Approve the plan before execution

## Suggested Work Loop for AI

1. Read this file (`AGENTS.md`) and `README.md`.
   Read `docs/README.md`, `docs/BRIEF.md`, `docs/HANDOFF.md`, and `docs/TODO.md` before starting work.
2. Edit TS behavior and Liquid markup in their correct layers.
3. Preserve `data-js` hooks unless intentionally migrating both TS + Liquid.
4. Run typecheck/build.
5. Update docs/todo when architecture contracts change.

## Project Tracking

- Follow the tracking workflow in [docs/README.md](docs/README.md).
- Keep confirmed scope and scope changes in `docs/BRIEF.md`; label unknowns and proposals explicitly.
- Maintain task status and completion criteria in `docs/TODO.md` using stable task IDs.
- After each work session, append changes and actual validation results to `docs/PROGRESS.md` and refresh `docs/HANDOFF.md` with current state, blockers, and the next action.
- Record consequential decisions and rationale in `docs/DECISIONS.md`.
- Do not invent historical completion, approved scope, or successful checks. Keep contributor rules in this file rather than duplicating them in tracking documents.

## Skill Workflow for Non-Trivial Changes

For changes bigger than a one-liner, use skills in this order — they operate at different stages, not all at once:

1. **`/caveman ultra`** — always on (see Response Style above). Governs tone only, doesn't affect analysis depth.
2. **`/junior-to-senior`** — before writing code, run this on the proposed plan/approach. It does adversarial codebase-grounded review and outputs a revised plan. Only proceed to implementation once this settles.
3. **`/ponytail`** — while implementing the reviewed plan. Forces the minimal, YAGNI-compliant version (reuse > stdlib > native > deps > one-liner) instead of over-engineered output.

`/grill-me` is currently broken (points to a non-existent `grilling` skill) and is excluded from this chain until fixed.
